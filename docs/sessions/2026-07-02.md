`BodyTooLargeError`, `ScheduleView` — kept as definitions or re-exports.

New layout:
- `src/http-util.ts` — `json`, `readBody`, `BodyTooLargeError`, `parseJsonBody`,
  `jsonBodyParseError`, `bearer`, `MAX_BODY_BYTES`, CORS allowlist + `corsHeaders`,
  `isOriginDenied`, `isSameOriginCaller`.
- `src/routes/types.ts` — `ServerContext` (resolved deps), `RequestContext`,
  route-spec types with an `auth: "none" | "same_origin" | "bearer"` discriminant so
  the ROUTER applies auth uniformly (no handler can diverge on auth).
- `src/routes/{meta,config,interests,briefs,schedule,chat}.ts` — route bodies moved
  verbatim with their PER-comment blocks.
- `src/routes/index.ts` — `V0_ROUTES` dispatch table (path → method → spec);
  `V0_ROUTE_METHODS` (405 Allow contract, PER-136) now DERIVED from the table so it
  can never drift.
- `server.ts` — preflight/PNA, /healthz, origin gate, uniform auth + dispatch,
  static fallback, 405/404 chain, `startServer`. `PKG_VERSION` moves to
  `build-info.ts` (provenance home; avoids a server↔routes import cycle),
  re-exported from server.ts.

Behavior-preservation notes (order-sensitive bits kept exactly):
1. OPTIONS preflight before URL parse; 2. /healthz before the origin-deny gate;
3. origin gate on `startsWith("/v0/")` before dispatch (unknown /v0 paths still 403
on denied origins); 4. auth before body parse (401 wins over 413/400); 5. dispatch
must `await` handlers inside the try so a throw still hits the logged-500 catch-all;
6. Allow-header method order preserved from the old V0_ROUTE_METHODS literals;
7. HEAD on /v0 routes still falls through to static→405 (dispatch is exact-method).

Validation after each step: `tsx --test test/*.test.ts` (152 tests), final
`tsc --noEmit` + eslint + duplication grep = 1.
